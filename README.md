# Мир мебели

Статический сайт мебельного магазина. Для локального просмотра откройте `index.html` или запустите `python3 -m http.server 8000` и перейдите на `http://localhost:8000`.

Изображения и тексты служат примером оформления: реальные товары, цены, адрес и контакты необходимо добавить после получения данных от владельца. Формы заказа и приёма платежей нет.

## Автоматическая публикация

Workflow `.github/workflows/deploy.yml` публикует статические файлы по SSH с помощью rsync при push в `main` или `arena/8fa9f243-mir`, а также вручную через Actions. Для работы нужен хостинг с SSH и rsync; каталог сайта должен уже существовать и быть доступным для записи. Домен `mir.ezegames.ru` должен быть направлен на этот хостинг, а веб-сервер — настроен на указанный каталог. DNS, веб-сервер и HTTPS workflow не настраивает.

В GitHub: **Settings → Secrets and variables → Actions → New repository secret** добавьте:

- `DEPLOY_HOST` — адрес SSH-сервера (без протокола и порта).
- `DEPLOY_USER` — пользователь SSH.
- `DEPLOY_PATH` — абсолютный путь к каталогу сайта (только буквы, цифры, `/`, `.`, `_`, `-`).
- `DEPLOY_KEY` — приватный SSH-ключ для этого пользователя; публичный ключ должен быть разрешён на сервере.
- `DEPLOY_KNOWN_HOSTS` — проверенная строка `known_hosts` SSH-сервера, полученная у хостинг-провайдера или проверенная по отпечатку ключа через доверенный канал. При нестандартном порте используется формат `[host]:port`.

При необходимости создайте repository variable `DEPLOY_PORT` (по умолчанию 22). Не отправляйте ключи в чат и не добавляйте их в репозиторий. После настройки запустите workflow вручную или отправьте новый commit. Без этих настроек публикация завершится ошибкой; файлы не будут загружены. Workflow не удаляет старые файлы на сервере.
